# 同济大学软件学院课程作业与课程项目

本仓库整理了在同济大学软件学院学习期间积累的部分课程作业、实验代码、课程设计和配套资料，主要使用 **C / C++**，涉及高级程序语言设计、程序设计范式、数据结构、离散数学，以及算法分析与设计的目录归档。

这里既有从输入输出、循环、函数开始的基础练习，也有链表、树、图、排序等数据结构应用，以及五子棋 AI、自走棋游戏等综合项目。希望这些资料能帮助你理解题目、比较实现思路，并回顾课程之间的联系。

> **使用前请注意：** 本仓库是历史学习成果的归档，包含早期练习、模板和未完成内容，不能将“目录中有文件”等同于“项目已完整可运行”。不同年份的课程要求可能不同，请以自己当年的课程安排和题目为准。

## 1. 高级程序语言设计

### 这门课学什么？

这门课是程序设计的基础训练，核心是把文字描述的问题拆成可以执行、可以检查的程序。学习内容从变量、表达式和输入输出开始，逐步扩展到分支、循环、函数、递归、数组、字符串、指针，以及结构体和类。

“高级程序语言”指 C / C++ 这样的编程语言，并不意味着一开始就学习复杂框架。对初学者而言，更重要的是理解程序的执行过程，掌握函数分解、输入检查、调试和代码规范。

## 2. 程序设计范式

### 这门课学什么？

程序设计范式关注如何组织解决问题的代码。本仓库中的相关作业主要体现了过程分解、类的封装、标准库容器与算法的使用，以及游戏项目中的模块划分和团队协作。

基础作业虽然题目规模不大，但可以用来比较不同解法：直接遍历与状态递推、排序与哈希、区间处理与滑动窗口。综合项目则进一步涉及界面、游戏状态、AI 决策和网络通信。

## 3. 数据结构课程设计

### 这门课学什么？

数据结构研究如何组织数据，以及如何高效地查询和修改数据。课程设计把线性表、链表、栈、树、图、字符串匹配和排序等知识放进具体场景，让你不仅能描述算法，还能实现完整的输入、处理和输出流程。

本仓库收录 **10 个独立课题**，各课题目录中包含 C++ 源码、Visual Studio 工程和对应 DOCX 文档。它们是不同程序，应分别构建与运行。

## 编译与运行说明

### 先判断是哪一种程序

| 类型 | 使用方式 | 当前限制 |
| --- | --- | --- |
| 单文件基础作业 | 单独编译对应 `.c` 或 `.cpp`，按提示输入数据。 | 部分代码依赖 MSVC 扩展或 Windows API。 |
| 多文件作业 / 控制台游戏 | 将同一题目的入口文件与所需实现文件加入同一个工程。 | 不要将多个带 `main()` 的独立程序放进同一个可执行项目。 |
| 数据结构、离散数学与范式作业 | 打开相应 `.vcxproj`；使用 `.sln` 前先核对项目路径。 | 当前三个课程解决方案中有 10 处失效路径。 |
| 自走棋客户端与服务端 | 补齐 Cocos2d-x 3.17.2，再分别配置客户端和服务端。 | 引擎目录未随仓库收录；客户端配置为 Win32 / x86。 |

### Windows / Visual Studio

现有大部分 `.vcxproj` 使用 **Visual Studio 2022 对应的 `v143` 工具集**；普通课程工程还指定了 Windows SDK `10.0`。构建时需要安装相应的 C++ 工具集和 SDK。

1. 进入要运行的具体作业目录，优先打开实际存在的 `.vcxproj`。
2. 选择合适的 Debug / Release 和平台配置；自走棋客户端使用 Win32。
3. 多文件作业应包含依赖的实现文件，避免遗漏函数定义。
4. 文件读取类题目需要检查工作目录，例如关键字检索程序使用文本文件时，应确保输入的路径可访问。
5. 若解决方案提示项目无法加载，核对 `.sln` 中记录的相对路径；目录改名后，旧路径不一定同步更新。

### 编码与跨平台

多数 C / C++ 源码不是 UTF-8，字节内容可按 **GB18030 / GBK 兼容编码**读取。中文注释出现乱码时，应先选择正确的编码打开；转换编码前建议保留原始版本，并确认编译器对源码及输出字符集的设置。

使用 `windows.h`、`conio.h`、`_getch()`、Windows 控制台工具或 Windows Socket 的程序，不能直接在 macOS / Linux 上按原样构建。仅使用标准库的独立练习可以尝试 GCC / Clang；涉及 `strcpy_s` 等 MSVC 特性的文件仍需处理平台差异。

例如，在确认源文件已是 UTF-8 且只依赖标准库后，可以单独编译：

```bash
clang++ -std=c++11 assignment.cpp -o assignment
./assignment
```

这只是单文件程序的使用示例，不是整个仓库的一键构建命令。

2. 自己尝试实现，再对照仓库中的思路。
3. 用正常情况、最小输入、边界输入和非法输入检查程序。
4. 记录实现的适用条件，并分析复杂度及可以改进的地方。
